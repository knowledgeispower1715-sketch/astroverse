**Classification:** Infrastructure, Deployment & Emergency Runbook

**Release Gate:** Zero Unverified Production Changes

## 1. Pre-Deployment Configuration Checklist

Before initiating any release to production, verify that all required environment variables are configured in the Vercel Project Dashboard:

| Variable | Environment | Sensitivity | Description |
| :--- | :--- | :--- | :--- |
| `DATABASE_URL` | Production | Critical | PgBouncer connection string (Port 6543) with `?pgbouncer=true` |
| `DIRECT_URL` | Production | Critical | Direct PostgreSQL connection string (Port 5432) for Prisma CLI migrations |
| `CASHFREE_APP_ID` | Production | High | Cashfree Payments Production Merchant App ID |
| `CASHFREE_SECRET_KEY` | Production | Critical | Cashfree Payments Production Merchant Secret Key |
| `CASHFREE_WEBHOOK_SECRET`| Production | Critical | HMAC-SHA256 signature verification secret for webhooks |
| `JWT_SECRET` | Production | Critical | Minimum 256-bit cryptographically secure random session signing key |
| `ADMIN_EMAILS_ALLOWLIST`| Production | High | Comma-separated allowlist of staff emails permitted admin access |
| `ALLOW_PRODUCTION_AUTO_DDL`| Production | Guard | Must be strictly set to `'0'` to prevent runtime schema mutations |

## 2. Database Migration Procedure

Automatic runtime schema alterations are disabled in production via `schemaBootstrap.ts`. All DDL must be applied via versioned Prisma migrations before deploying code changes:

```bash
# 1. Inspect pending migrations against staging/production
npx prisma migrate status --schema=services/wallet-service/prisma/schema.prisma

# 2. Apply pending migrations safely
npx prisma migrate deploy --schema=services/wallet-service/prisma/schema.prisma

# 3. Verify database connectivity and schema readiness
curl -s https://astroverse-eta.vercel.app/api/ready | jq .
# Expected output: { "status": "READY", "persistence": "POSTGRES_PRISMA", "supabaseConnected": true }
```

## 3. Git Branching, Build & Vercel Deployment

1. **Feature Branch:** Develop all changes on an isolated branch (e.g. `feature/platform-audit-repair-verification`).
2. **Local Pre-Flight Gate:**
   ```bash
   # Run all wallet service test suites
   npm test --prefix services/wallet-service

   # Run Python Kundli Engine tests
   cd services/kundli-engine && pytest && cd ../..
   ```
3. **Commit Convention:** Format commits using Conventional Commits (`feat:`, `fix:`, `chore:`).
4. **Push & Vercel Preview:**
   ```bash
   git push origin feature/platform-audit-repair-verification
   ```
   Inspect the Vercel Preview URL generated by GitHub integration to confirm clean visual and network rendering.
5. **Production Merge & Promotion:**
   Merge approved PR into `main`. Vercel automatically deploys `main` to `https://astroverse-eta.vercel.app/`.

## 4. Cashfree Merchant Dashboard Configuration

1. Log into the Cashfree Merchant Control Center (`https://merchant.cashfree.com/`).
2. Navigate to **Payment Gateway > Developers > Webhooks**.
3. Add or verify the active Webhook Endpoint:
   - **URL:** `https://astroverse-eta.vercel.app/api/webhooks/cashfree`
   - **API Version:** `2026-01-01`
   - **Subscribed Events:** `PAYMENT_SUCCESS_WEBHOOK`, `REFUND_STATUS_WEBHOOK`, `SUBSCRIPTION_STATUS_WEBHOOK`
4. Copy the webhook secret and ensure it matches `CASHFREE_WEBHOOK_SECRET` in Vercel.

## 5. Emergency Rollback & Disaster Recovery Procedures

### 5.1 Instant Edge Rollback (Under 30 Seconds)
If an unexpected defect manifests in production:
1. Open the Vercel Project Dashboard (`https://vercel.com/astroverse`).
2. Navigate to **Deployments**.
3. Locate the previous healthy deployment (e.g., baseline commit `ac67a4738`).
4. Click the three dots (`...`) and select **Instant Rollback**.
5. Traffic is immediately redirected to the prior build at the edge.

### 5.2 Database Point-in-Time Recovery (PITR)
If an accidental data corruption occurs:
1. Open the Supabase Project Dashboard.
2. Navigate to **Database > Backups > Point in Time Recovery**.
3. Select the timestamp immediately preceding the incident and restore to a target branch or instance.
